### 6.1 已定的设计决定

| 项 | 决定 | 理由 |
|---|---|---|
| 前端 | Worker 输出 HTML，**不上 React、不用 Pages** | 用户要「读懂代码」；XMUHub 实证纯静态可行；工作量最小 |
| 存储 | 存储抽象层（可插拔）+ `material_sources` 表 | 数据可迁移，不绑死单一供应商；将来加第二源不改业务代码 |
| 去中心化范围 | 只做「可插拔 + 可迁移」（层次一+二），**不做无中心架构** | 无中心 = 无人负责，与「必须拦住高危内容」冲突；对个人风险最高 |
| 第一版存储源 | R2 | 10GB 免费 + 下载流量永久免费 |
| 准入机制 | **做进第一版**（双通道 + 拦截留痕），词表留空待填 | 上线前必须有；上云后再加要动已跑起来的代码 |
| 部署前 | 必须本地 `wrangler dev` 跑通 + 验证脚本通过 | 不烧额度、可反复测；符合「上线前就该处理」原则 |
| 账号 | **必须用户本人注册** | 署名、责任、AGPL 归属；不可代开 |
| 代码目录 | `D:\AI输出的文件\project_ldsg_cloud\`（与本机版分开） | 本机版是唯一验证过的版本，不污染 |
| 谁写码 | **codex 写**，Hermes 出交底书 + 独立验收 | 既定分工 |

### 6.2 云端准入设计（核心）

**按内容性质分两条通路，不是「严」「松」的程度问题：**

| | 版权类（教师PPT、旧卷、教材） | 高危类（高法律风险内容） |
|---|---|---|
| 策略 | **先上后诉**（默认放行，投诉即下架） | **事前防火墙拦截**（默认拒绝，无免审通道） |
| 依据 | 逐份判授权不现实，判错代价只是「被要求下架」 | 「上线过」本身就是伤害，截图不可逆 |
| 位置 | 正常待审队列 | **在落存储之前拦截**，不进队列、不落库 |

**防火墙形态（三道叠加，纯技术拦不住，必须靠结构）：**

1. **通道收窄**：压缩包 / 图片 / 纯文本走更严通道（压缩包能藏任何东西，图片能藏内容）
2. **命中即拒**：关键词表命中 → 当场拒绝 + 留痕，不走「挂起」
3. **强制人审**：文本 / 图片 / 压缩包 100% 人工过目，无免审通道

**拦截留痕**：新建独立日志（区别于 `audit_log`），记录「谁在什么时候传了什么、被哪条规则拦了」——这是给运营者自己的保护。

## 七、外部调研结论（已查实）

### 7.1 XMUHub（厦门大学·鹭岛书阁）

- 仓库：https://github.com/vintcessun/XMUHub （Rust + Axum + redb，AGPL-3.0，37★）
- **前端实为纯静态 HTML**（54KB app.css，零构建）—— **不是 React**，印证「不上 React」更对
- 移动端处理：一个 viewport + 15 个响应式断点（720/640/520/480px），**从不判断设备品牌**，安卓 iOS 通吃
- 存储：文件存 GitHub Releases（私有仓库），**服务器不经手文件字节**（写进 AGENTS.md 硬规则）
- 准入：**只做技术性拦截（大小），内容判断全交给「人审 + 投诉 + 五状态机」**；唯一的自动化是导入时按文件名关键词字面匹配（`勿外传/仅内部/密码` → restricted）
- 状态机：`pending / published / rejected / removed / restricted`
- 经验证实的：它踩过一个坑——有人加「服务器兜底下载」接口，违背原则被回退，专门写进文档「不要再加回来」

### 7.2 ARK ALL（澳门大学）

- 学生自发开发运营、非官方、21000+ 用户、高峰日活 4700
- **在校园内有公开广告**（校方知道其存在，未制止）
- 证明：**澳大对非官方学生校园项目持默认容忍态度**
- **不能证明**：它没有「开放上传的文件共享」功能（项目书 2.3 节已写明），所以它不构成「开放上传在澳门安全」的先例

### 7.3 已排除的错误结论

- ❌ 「有人在专门反对 XMUHub」——查实 `antivintces/anti_vintces` 是俄乌战争的浏览器刷流量页面，与本项目无关（此结论已收回）
